# Immersive IP Website

## 目标

把角色素材变成页面目标明确、视觉关系成立、互动结果可理解、在目标设备上真实可用的网站。设计从访问者需要看见、理解或完成什么开始，不从现有文案、角色标签、惯用场景或固定交互开始。

用户只要求讨论、评审、候选方向或提示词时，停在相应结果；要求制作或修复时，完成授权范围内的实现，并沿真实素材、正式状态和最终页面验收。

## 不越过的边界

- 设定图只提供可见的身份、外观、服装、材质和原设配饰，不自动提供性格、动作、环境、职业、剧情或世界观。
- 旧网页文案、文件名、历史提示词和模型新增元素不是角色事实，除非用户明确确认。
- 参考站只约束用户点名借用的部分；互动、构图、色彩、字体、文案和品牌语言分别判断。
- 素材的生产职责和实体文件权限分开。用户要求不再使用时先移除全部活动引用；归档或删除仍需相应授权。
- 用户选定的视觉稿、文案和保留范围成为当前真源。局部修改只改变点名变量，被否定方案不得混回有效基线。
- 不把某次动作、环境、版式、转场参数、媒体数量或页面顺序保存成后续项目默认。
- 未经授权不替换角色设定、扩写世界观、删除素材、安装依赖、生成媒体、打包、发布或推送网站。
- 浏览器标签布局、扩展注入层和操作系统浮层不属于页面实现边界；先确认控制者，再决定是否进入项目。

## 正常工作

### 1. 冻结当前请求、事实和权限

先确认本轮要交付的是目标与设计讨论、候选方向、提示词、真实素材处理、网站实现或修复，还是只读验收。用户明确要求直接实现且关键决定已有真源时继续执行；询问意见或要求先看方案不构成生成和写入授权。

事实按职责读取：

- 角色事实来自设定图与用户确认；
- 网站事实来自当前运行页面、设计系统和真实容器；
- 媒体事实来自实际文件、画面、编码和可用区间；
- 页面目的、动作、环境、文案和保留范围来自用户最新决定。

精确替换文案时保留文字、标点、大小写和有意义的换行。尺寸、比例、远近、拥挤或完整显示存在歧义时，先读取真实媒体与页面几何，区分源像素、长宽比、显示宽高、视觉权重、裁切、间距和遮挡；只有证据仍无法决定且不同解释会改变结果时才追问。

### 2. 先判断页面是否需要，再定义结果

每个页面或章节都要承担独立信息、探索方式、内容证据或行动入口。没有独立结果、与其它页面重复且缺少可靠内容时，优先提出合并、改名或移除，不为了导航数量和视觉对称强行保留。

从零规划、重大改版、页面取舍或身份迁移时完整读取 `references/project-brief-template.md`。至少明确：

- 页面完整展示什么，访问者第一眼看什么；
- 访问者怎样探索，探索后新增什么信息；
- 页面与全站靠哪些视觉关系保持一致；
- 必须保留、允许改变和仍待确认的内容；
- 每段文字与控件承担身份、说明、状态、选择、提示还是行动。

无职责文案不用于填空或平衡构图；空间关系由设计解决。

### 3. 建立视觉、媒体和集合合同

明显涉及审美判断、素材生成或较大版式变化时，先说明页面目标、已确认事实、媒体与技术限制、准备比较的设计变量，以及确认后的交付。需要候选时提供二到三个空间关系、信息层级或互动机制真正不同的方向；用户选定或授权 AI 决定后再生产。

进入提示词、媒体制作或视觉还原前，完整读取 `references/creative-and-media-workflow.md`。它负责：

- 角色、动作、环境、网站构图和安全区的唯一真源；
- 选定视觉的几何、比例、负空间、色彩和文字关系；
- 原始比例、显示尺度、视觉权重以及整景或分层媒体；
- 语义运动与几何运动、关键帧链、提示词、真实成片检查和生产记录；
- 循环、转场、透明媒体、poster、格式与交付清单。

同时展示两项以上媒体时，先建立正式条目与顺序、数量范围、真实比例、显示基准、裁切、分组、间距、遮挡、当前选择、目标视口和减少动态效果合同。排布由目录、容器、媒体比例和视口共同派生；可扩展集合不得为每项维护第二套位置和尺寸。

### 4. 先定义互动结果，再选择运行结构

每项互动写清输入、生效区域、取样对象、反馈位置与内容、可打断性、触摸或键盘替代和结束状态。布局层、运动层和命中层分别负责稳定终点、视觉变化和可操作范围，不能共同写同一最终变换。

需要媒体选择、预热、帧驱动互动、动画定位、导航恢复、离散滚轮或章节运行边界时，完整读取 `references/interaction-director.md`。它负责参数空间、最小运行结构、唯一媒体清单、最终消费者预热、异步归属、请求仲裁、循环、章节、目录、声音和减少动态效果。

新增或重构 sticky、固定舞台、滚动驱动、Canvas 或多媒体性能链路时，再完整读取 `references/scroll-performance.md`，先确定唯一输入和进度所有者、真实可视高度、交互媒体预算、渲染与解码责任，再编码。

页面身份、显示名称、顺序、渲染、导航、URL、历史和媒体预热从同一稳定注册产生。页面改名、合并或移除时迁移全部消费者，原行动明确转移或取消，旧身份不再可导航、渲染、恢复或请求。

### 5. 沿唯一边界实施

只建立当前复杂度确实需要的单一来源：页面顺序、视觉与素材合同、媒体清单、当前选择、互动命中几何、连续进度和预热状态。目录渲染、读数、可访问名称和预热目标读取同一正式目录；品牌母版及其页眉、favicon、应用清单、加载界面、分享图和烘焙媒体消费者一次迁移。

实现和修复沿以下链路收口：

真实生产者 → 状态、存储或传输边界 → 正式消费者 → 用户可见结果

预加载必须给最终播放器、图片节点或可原子晋升的备用消费者挂载真实目标并完成解码；临时元素、测试 URL、空任务和手写 ready 不能冒充完成。poster 或静态锚点保持到同一消费者出现可解码画面，失败时页面仍保留可用内容与导航。

根因修复完成后移除旧监听、旧 helper、旧状态、旧恢复路径和旧导出，不保留兼容层或半迁移架构。

### 6. 用真实页面验收

网站实现、修复、迁移完成后或只读验收时，完整读取 `references/browser-acceptance.md`。至少覆盖用户问题的精确视口，再按实际需要检查超宽屏、常规桌面、低高度、窄屏、移动端和减少动态效果。

证明真实素材和状态从正式入口产生请求，经最终消费者解码并形成可见结果；分别检查首次绘制、poster、预加载复用、响应式构图、媒体集合、互动命中、循环、异步选择、滚动演出、刷新、站内导航、前进后退和页面缓存恢复。

截图只证明最终视觉关系；几何、手势、时序和预热还要读取真实尺寸、事件序列、节点身份、currentSrc 和请求状态。验收证据只覆盖生成时的文件状态；之后影响页面、媒体、样式、清单或测试的修改会使相关证据失效。

## 输出

先给用户能观察到的结论，再说明必要依据：

- 设计讨论：页面目标、事实与限制、候选方向、差异和下一步。
- 提示词：简短来源说明和一份围绕单一画面或相邻关键状态的可复制提示词。
- 实现或修复：完成结果、根因、修改边界、真实浏览器证据和未验证项。
- 只读验收：通过、未通过、实际证据和影响。

不输出工具流水账，不用未经确认的角色文案替代视觉判断，也不把当前任务的失败经过或具体参数写回本 Skill。
